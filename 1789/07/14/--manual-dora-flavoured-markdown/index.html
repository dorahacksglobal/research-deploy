Dora-flavoured Markdown

14 Jul 1789

Zhengyu Qian

Markdown 首先是一种写作方式

  • Markdown 是纯文本。
  • Markdown 让作者摆脱了繁琐的排版样式设定，专注于文章结构，用简约的符号进行语义化标记（semantic markup）。
  • Markdown 的标记符号源自纯文本电子邮件的时代。
  • 掌握了 Markdown 语法的书写者，可以用纯文本的方式直接沟通——使用「方言」也无妨；内容结构和语义标记跃然纸上，无需额外样式；标记符号直观可读。

John Gruber 是 Markdown 最初的创作者之一，他清晰地描述了 Markdown 的主旨及基本语法。

Dora-flavoured Markdown

在基本语法之上，我们可以按需扩展或定制一些特殊标记，形成 Markdown「方言」（flavour）。开发者社区中，一些方言（如 GFM）已广泛通行。

Dora-flavoured Markdown (DfM) 是为 Dora Research 定制的 Markdown 方言，除了基本语法，可额外支持：

  • 含图注的通栏图片；
  • 脚注；
  • 语法高亮的代码模块；
  • LaTeX 语法的数学公式。

在技术上，Markdown 通常先转换为 HTML（或类似的结构化标记文本），再被渲染成富文本样式。因此 Markdown 天然兼容 HTML 语法，我们随时可在 Markdown 里直接写 HTML。

通栏图片及图注

图片标记 ![]() 独立成段时，DfM 会将其转换为通栏图片，并可支持图注：

![This is figure caption](https://dorahacksglobal.github.io/images/image/20211017-chackathon.png "This is image title")

渲染效果如下：

  • 图片标题 "This is image title" 可省略；填上它有助于无障碍阅读（盲人使用的屏幕阅读器）和搜索引擎优化。
  • 图注区域 This is figure caption 支持简单的 Markdown 语法，例如 *emphasis*、**strong** 和 [link](url)。

上述 Markdown 标记在渲染后，实际被转换成如下 HTML（当然，我们也可以在 Markdown 里直接写 HTML，它的自由度更高）：

<figure>
  <img src="https://dorahacksglobal.github.io/images/image/20211017-hackathon-dao.png" title="This is image title" />
  <figcaption>This is figure caption</figcaption>
</figure>

行内图片不会转换：

This ![](https://doraresear.ch/assets/favicon-128.png "Image title") is an inline image.

渲染效果如下：

This is an inline image.

脚注

DfM 支持当下最通行的脚注扩展语法之一，GitHub 团队简明地介绍过。

There is something[^1] that needs a footnote.

[^1]: This is the footnote.

There is also something[^x] that needs another footnote.

[^x]: This is another footnote.
  • 上尖号 ^ 是这组标记中唯一关键的符号；
  • 可以用任意字母、数字或符号去代替具体的索引编号；
  • 脚注的详情，可以分散在正文各处。

渲染后，全文脚注会被自动收集，按行文顺序重新编号索引；注释详情集中排版在文章末尾。渲染后的脚注会附带必要的交互功能和视觉样式。

编程语言的语法高亮

DfM 的语法高亮，基于「围栏式代码模块」（fenced code block）而扩展。围栏式代码模块是当下通行的 Markdown 扩展语法，以一对 ``` 标记将代码模块包围。

DfM 的标记方法与 GitHub 相同。也即，在开头的围栏标记后附加上编程语言名称（例如 ```javascript），渲染后即可实现句法分析及染色：

```javascript
// Import
import { ApiPromise, WsProvider } from '@polkadot/api';

// Construct
const wsProvider = new WsProvider('wss://rpc.polkadot.io');
const api = await ApiPromise.create({ provider: wsProvider });

// Do something
console.log(api.genesisHash.toHex());
```

渲染效果如下：

数学公式

  • 数学公式的标记方式跟代码的标记很类似，只是符号替换成了 $ 和 $$：
    • 用一对 $ 包围的公式代码，会渲染为行内的公式片段；
    • 用一对 $$ 包围并独立成段的公式代码，会渲染为独立的公式模块。
  • DfM 基于 MathJax 实现数学公式，支持 语法；一些在线的公式编辑器（例如 Mathcha）可能会有帮助。

其他语义性指南

正文标题层级

  • 支持 H1–H6 六级小标题，请优先使用 H2、H3、H4。
  • 如果正文只需一个层级的小标题，可考虑优先使用 H3。
  • 慎用 H1、H5 和 H6；DfM 的 H5 和 H6 会渲染为意大利（斜）体，请暂时不要用于中文。
## Heading level 2
### Heading level 3
#### Heading level 4

强调语义及适用范围

  • 在英语书写中，单词首字母大写或全大写，就可以表示强调；但务必慎用全大写的句子或段落。
  • *emphasis* 的强调性弱于 **strong**，在英语文章中使用 *emphasis* 显得温和而优雅。
  • 在 DfM 中，emphasis 会渲染为意大利（斜）体，strong 会被加粗；因此 *emphasis* 暂时不要用于中文。
  • 大写、*emphasis*、**strong**，三者可按需叠加使用。
  • 虽然下划线是超链接的默认样式，但有时也可用于强调或突出；直接使用 HTML 标签 <u> 即可。

标记方法如下：

ALL CAPITALS is a way to express emphasis while it may be considered rude.
This is an *emphasis* word. This is a **strong** word.
This is a ***strong & emphasis*** phrase.
This is an <u>underlined</u> word.

渲染效果如下：

ALL CAPITALS is a way to express emphasis while it may be considered rude.
This is an emphasis word. This is a strong word.
This is a strong & emphasis phrase.
This is an underlined word.

*emphasis* 不是「斜体」

  • *emphasis* 是语义标记，不是样式标记。
  • 如需将某些文本在视觉上标记为「斜体」（例如，英语行文中的拉丁语词），可使用 HTML 标签 <i>。
  • 标记作品名称（例如，英语书名），可使用 HTML 标签 <cite>。

标记方法如下：

The Latin <i>cogito, ergo sum</i>, translated into English as “I think, therefore I am”.
<cite>Gone with the Wind</cite> is a novel by American writer Margaret Mitchell.

渲染效果如下：

The Latin cogito, ergo sum, translated into English as “I think, therefore I am”.
Gone with the Wind is a novel by American writer Margaret Mitchell.

为什么「意大利（斜）体」（italic）不适合中文？

  • 意大利体不是斜体。
  • 意大利体（italic type）是一种拉丁字母书写体的大分类，与之对应的是罗马体（roman type）和哥特体（black letter）等等。
  • 罗马体（roman type）字母通常是直立的（因而被误译作「正体」），意大利体（italic type）通常微微倾斜（因而被误译作「斜体」）——但倾斜与否不是两者最本质的差异，相关细节繁杂，此处不展开。
  • 不太严谨地，罗马体可类比「宋体」，意大利体可类比「楷体」。

囿于现状，操作系统中适合网页使用的中文字体极少，而引入中文 webfont 的副作用又较多；故中文 italic 样式所需的字体在事实上是缺失的。在没有字体支持的情况下，浏览器会将汉字机械变形，转换为「伪斜体」来匹配 italic 样式，阅读体验较差，因此须避免使用。

DfM 的段落引用（block quote）样式使用了意大利斜体，但对中文文章（lang: zh）有特殊优化，可避免出现伪斜体。

Dora-flavoured Markdown 根据 Dora Research 的文章内容、字体排印及写作风格需要，杂糅了一些常见的 Markdown 语法扩展，也约定了部分语义标记的使用方法，但尚不成熟完备。DfM 中各种标记所渲染的视觉样式也可能持续迭代。

DfM 目前的实现，基于如下开源项目：

  • hexo
  • hexo-filter-mathjax
  • hexo-renderer-markdown-it
  • markdown-it-implicit-figures

在使用中如遇出错或费解，请随时联系开发者。
